# ⚙️ 核心与平台配置详解

Get Jobs 提供了开箱即用的前端 Web 控制面板，所有常规筛选参数均可在前端交互式勾选并一键保存到本地 SQLite 数据库中。

---

## 1. 基础全局配置

在控制面板的“系统设置”或配置文件中，你可以定义以下全局投递策略：

| 配置项 | 说明与建议值 |
| :--- | :--- |
| **目标城市** | 支持多选（如：北京、上海、杭州、深圳、广州等） |
| **岗位搜索关键词** | 例如：`Java`、`前端`、`大模型算法`、`全栈开发` |
| **期望薪资区间** | 例如：`15-25k`，程序会自动过滤低于该区间的职位 |
| **经验与学历要求** | 过滤不符合个人履历的硬性门槛（如硕士限定、5年以上等） |
| **每日投递目标数** | 建议控制在各平台官方安全限制阈值内 |

## 2. 各招聘平台专属配置

### 🟢 Boss直聘配置

#### 向已沟通 Boss 再次发送消息

在管理页「Boss直聘 → 投递行为」中切换此拨片，默认关闭。

- **关闭**：按钮为「继续沟通」时跳过该岗位，继续处理下一个。
- **开启**：点击「继续沟通」后，再次发送 AI 或默认打招呼语；若 AI 判断不匹配，仍按原规则跳过。
- 修改后点击「保存配置」，在下次启动投递时生效。「立即沟通」不受此开关影响，图片简历由原有独立开关控制。

旧数据库在启动时自动补充此配置，默认关闭，保留已有设置。

- **打招呼限额**：目前平台限制单日约 150 次。
- **自定义打招呼语**：
  - 若开启 AI 打招呼模式，系统将动态调用模型结合你的简历和 JD 生成；
  - 若未开启 AI，请务必在配置项中预留默认打招呼语文本，否则可能导致投递中断。
- **图片简历（`sendImgResume`）**：
  - 设为 `true` 后，打招呼成功的同时自动向 HR 附送预先转换好的 `resume.jpg` 图片简历。
- **黑名单自学习机制**：
  - 系统在遍历沟通记录时，如果检测到 HR 回复“不合适”、“已招满”等关键词，会自动将该企业记录至黑名单中，未来绝不重复打扰。

## 3. Cookie 管理与扫码登录

Get Jobs 使用扫码登录与本地登录态管理。具体登录方式以平台页面为准，猎聘与智联按 README 要求使用绑定微信的账号：

1. **自动调起**：点击平台“登录/扫码”按钮后，本地会自动调起浏览器窗口并打开平台登录页。
2. **手机扫码**：在弹出的浏览器中，使用手机端对应 App 扫码确认。
3. **安全持久化**：登录成功后，程序在本机保存登录状态。请妥善保护本地 Cookie、浏览器数据与数据库，不要上传或分享这些文件。
4. **免重新扫码**：绝大多数平台 Cookie 有效期在 3~7 天以上，过期前无需反复扫码。

::: warning 平台维护范围
README 明确说明当前维护 Boss 和猎聘，51job、智联、拉勾已停止维护。上述旧平台说明供已有用户参考，不代表当前版本可正常投递。
:::
